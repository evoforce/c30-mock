## M3 架构回顾 + C++ 迁移评估 + 局域网优化(2026-11-17 深夜)
- **架构回顾结论**:数据层(Stroke 纯数据/压感算法/协议)与渲染完全解耦,可无缝迁移 C++;但渲染层未真正抽象(renderStroke 是组件内闭包,未落地文档设计的 Renderer 接口),且存在 O(n²) 全量重发 + 全量重绘两个性能隐患。
- **用户决策**:①先修延迟+抽渲染接口(纯 JS 零新依赖);②局域网采用"双轨自动降级"(优先直连教师,mDNS 失败回退中心服务器)。
- **已落地三项**:
  1. **stroke.live 增量点发送**:LiveStrokeDelta{id,delta,done},教师端 pointermove 只发新增点(sentCountRef 追踪),消除 O(n²) 全量重发;学生端 liveStrokesRef(Map<id,Stroke>) 本地累积 delta。
  2. **抽 Renderer 接口**:新建 components/Renderer.ts,定义 Renderer 接口(render/renderIncremental/renderLive/remove/clear/resize)+ CanvasRenderer 实现(核心 drawStroke 唯一依赖 Canvas API 的地方)。Whiteboard.tsx 改用 rendererRef,未来换 NativeRenderer(C++)只换实现类。
  3. **mDNS 双轨直连**:mdsd 包用 bonjour-service 真实实现(教师端 publish 广播 roomCode/teacherName/host/port,学生端 subscribe 发现)。教师端主进程内嵌 socket.io server(localSessionServer.ts,监听 0 端口+0.0.0.0,复用 NestJS 协议内存版),mDNS 广播;学生端主进程订阅发现+IPC 通知 renderer;双端 renderer 连接逻辑改为"优先直连内嵌 server,connect_error 回退中心 127.0.0.1:3000"。学生端 UI 显示"局域网直连/服务器中继"模式。
- **关键架构决策**:教师端 renderer 也优先连内嵌 server(而非中心服务器),保证教师+学生落在同一套房间状态(否则 roomCode 不互通)。中心服务器仅作降级/云同步。
- **依赖**:pnpm add bonjour-service --filter @c30/mdsd;pnpm add socket.io --filter @c30/teacher。
- **坑**:socket.io 4.8 的 Server.listen 只接受(srv|number, opts?),不接受 callback 和 host;绑定 host 须用 http.createServer()+io.attach()+httpServer.listen(port,host,cb)。已用此方案解决。catch(err) 的 err 在严格模式是 unknown,访问 .message 需 as Error 断言。
- 验证:两端 tsc 全净(仅既有 TitleBar WebkitAppRegion);electron-vite build 通过;内嵌 server 用独立 node 脚本验证 listen(0)端口分配+session.create 协议链路正常。
